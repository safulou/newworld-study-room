### 3. 技術細節

- **Web Audio AnalyserNode 並聯旁路與高性能高幀率 Canvas 示波渲染**：
  - 在立體聲母帶架構中，將 `this.analyser` 以並聯分支形式連接於 `this.masterGain`，訊號流不經過分析節點直接進入 `destination`，徹底杜絕分析操作對主音訊鏈的相位或頻率響應產生任何干擾。
  - 設定 `fftSize: 128`，頻率資料陣列僅有 64 個取樣點，計算負荷極低；示波器主循環將其降採樣為 32 個精華頻段，配合 `Math.round(width * dpr)` 與 `ctx.scale(dpr, dpr)` 繪製於 Retina 畫布上，在任何高解析度螢幕（4K、Retina）均維持清晰邊緣與 60fps 平滑渲染。
- **贈禮資料防膨脹消毒與離線無伺服器持久化架構**：
  - 贈禮收藏盒完全不依賴遠端伺服器儲存。在 `store.js` 的 `sanitizeProfile` 中，對收到的 `receivedBookmarks` 進行嚴格的型別過濾與最大長度截斷（`slice(0, 40)`），即便長期頻繁與書伴連線互動，本機 localStorage 依然保持在數十 KB 的極輕量範圍。
- **成就元資料結構化與實時進度計算**：
  - 每項成就均回傳結構化的 `progressPercent: number` (0~100) 與 `progressText: string`，讓前端 UI 能以簡潔宣告式方式直接產生漸變進度條與「3/5 種」、「7/10 輪」等數值提示，消除原本黑盒鎖定狀態帶來的挫折感。

### 4. 遇到的問題與解決方案

- **單元測試中 goal_achiever 成就未依預期解鎖**：
  - _問題_：`study-stats.test.js` 傳入 `{ dailyGoalAchieved: true }`，而 `study-stats.js` 內部原先僅檢查 `extraState.dailyGoalCompleted`，導致斷言失敗。
  - _解法_：於 `study-stats.js` 中將判定改為 `Boolean(extraState.dailyGoalAchieved || extraState.dailyGoalCompleted || ...)`，雙向相容測試與實際業務呼叫。
- **折疊面板時的動畫節能處理**：
  - _問題_：當使用者收起聲學控制台時，若 `requestAnimationFrame` 仍持續執行像素填充與漸變運算，會不必要地消耗行動設備電量。
  - _解法_：在 `renderVisualizer()` 繪製循環開頭加入 `if (elements.acousticFxPanel && elements.acousticFxPanel.hidden) return;` 輕量返回檢查，展開時即刻自然恢復繪製。

### 3. 技術細節

- **Web Audio AudioParam 原生硬體加速 LFO 旁路調制**：
  - 傳統前端聲相動畫多仰賴 `requestAnimationFrame` 持續計算正弦波並賦值給 `panner.pan.value`，這不僅佔用主線程 CPU，在瀏覽器分頁背景運行或螢幕休眠時還會被節流降頻。
  - 本次實作將 `OscillatorNode` 輸出直接連向 `GainNode`（控制振幅），再直連 `StereoPannerNode.pan`（`AudioParam`）。全過程由瀏覽器音訊混合線程以 44.1/48 kHz 原生速率硬體插值運算，不僅零 CPU 負荷，即便在背景最小化分頁也能維持精準流暢的微風環繞感。
- **錯頻相位自旋矩陣演算法（Staggered Phase Rotation Matrix）**：
  - 各音軌並非以相同週期同步左右搖擺（否則會導致整體聽感生硬同相側傾），而是依軌道名稱計算獨立的頻率微差（0.035 Hz ~ 0.045 Hz）與相位反轉。例如雨聲偏左漂移時柴火正向右輕拂，營造出宛若真實林間微風徐徐流動的自然包裹感。
- **雙向社交信物狀態收斂與防重複回謝保護**：
  - 書伴收到書籤贈禮後，透過 `markBookmarkGratitudeSent` 即時在本地狀態標記 `gratitudeSent: true`，防範使用者重複發送空中回禮造成信號洗版；同時即便離線或同伴已離線，回謝心意依然記錄在本地圖鑑櫃中。

### 4. 遇到的問題與解決方案

- **番茄鐘模式列舉命名不一致**：
  - _問題_：`AmbientSoundscapeManager.setAtmosphereMode` 原先僅比對 `"break"`，而 `FocusTimer` 發出的事件模式為 `"shortBreak"` 與 `"longBreak"`，導致情境音景切換未被正確觸發。
  - _解法_：於 `setAtmosphereMode` 開頭加入正規化邏輯 `const normalizedMode = (mode === "shortBreak" || mode === "longBreak" || mode === "break") ? "break" : mode;`，徹底消除模式字串不一致的問題並相容單元測試。
- **動態新增軌道之調相器生命週期管理**：
  - _問題_：若使用者在「環繞微風」啟動狀態下開關不同的白噪音軌道（例如新開啟柴火或黑膠），新建軌道原本會以靜態向位初始化。
  - _解法_：抽取 `_registerTrack(name, trackNode)` 統一管理註冊流程，只要 `this.orbitingBreeze` 為 true，新註冊軌道即刻自動掛載對應的低頻調相器。
